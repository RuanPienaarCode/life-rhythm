2. Problem statement

Three plugins cover one job — what to do today, this fortnight, and as a habit — and they keep re-implementing each other. Rhythm's notes are read and written by four separate code copies (Rhythm, Fortnight, Vista, and Vista's calendar via the metadata cache); Tasks lines are parsed three ways; Vista and Fortnight reach into Nudge's private store and Rhythm's settings. The copies have already drifted (Fortnight's reader ignores goals and keeps area wikilink brackets; its vendored model is two commits stale). Each drift is a chance to write a note wrongly, and each fix must land in up to four places.

The cost of not merging: three ribbons, three settings screens, two ICS meanings, and every Rhythm data-safety fix reviewed four times.

3. Goals

  • One plugin, one view, seven pages, one ribbon — every feature of all three plugins still present.
  • One writer per note: Rhythm's notes are written only by Rhythm's io.js; the reminders note only by the reminders store.
  • Zero setting lost: a first load imports Nudge's and Fortnight's settings from their data.json without changing those files.
  • The phone calendar feed keeps working untouched: same path, same event UIDs, byte-identical for the same reminders.
  • Vista touches no planner file; it reads and ticks only through api apiVersion: 1.
  • All 37 existing test files from the three repos pass in rhythm-vault, plus new tests for import, ICS, API and Vista's adapter.

4. Non-goals

  • Trimming overlaps (Rhythm Plan/Week vs the Fortnight board, two quick-add parsers) — a separate pass after cutover (Q1).
  • Nudge's glass looks (surface, tint, mode) and Fortnight's accent choice — the whole view uses Rhythm's look (Q14).
  • Rewriting hotkeys.json — hotkeys bound to old command ids are listed for manual rebinding (Q10).
  • A Fortnight card on Vista — the API ships without a fortnight section (Q21).
  • Community-store submission of Rhythm; Nudge's pending first release is abandoned (Q25).
  • Any vault other than Pienaar Vault — no other vault has these plugins.

5. Users & access model

One user (Ruan), on desktop and iPhone, in one local Obsidian vault synced by iCloud. No accounts, no auth, no network except Rhythm's existing subscribed-calendar fetch. Other plugins (Vista) are the only programmatic consumers, through app.plugins.plugins.rhythm.api.

6. User stories

One place

v1As Ruan, I want one Rhythm view with Today · Reminders · Fortnight · Week · Month · Plan · Areas so that daily, two-week and habit planning live behind one icon.

v1As Ruan, I want each open pane to remember its page so that I can keep Fortnight beside Today.

v1As Ruan, I want "Open Reminders" / "Open Fortnight" commands and the old obsidian://nudge-reminders links to open the right page so that my Shortcuts keep working.

Reminders

v1As Ruan, I want the compass ribbon to show how many reminders are due and to be told when one comes due, even with the view closed.

v1As Ruan, I want my phone's subscribed reminders calendar to carry on without re-subscribing or duplicate events.

Planning and practices

v1As Ruan, I want Fortnight to plan practices through Rhythm's own writer so that a promise made on the board reads back exactly in Rhythm.

v1As Ruan, I want a tick to refuse rather than overwrite when a day's note has a list line the reader can't parse.

Settings and switch-over

v1As Ruan, I want my Nudge and Fortnight settings carried over automatically on first load so that nothing has to be re-entered.

v1As Ruan, I want a dated backup of the four installed plugin folders before switch-over so that rollback is "put four folders back".

Vista

v1As Ruan, I want Vista's Reminders and Today cards to read and tick through Rhythm's API so that only one plugin ever writes my notes.

API contract (Q19)

api.apiVersion === 1
api.onChange(cb) → unsubscribe()
api.weekStart() → 0 | 1
api.reminders.notePath() → string
api.reminders.summary({ today, limit }) → { available, path, rows, buckets, counts, more }   // rows carry ref
api.reminders.toggle(ref, { today })      → { ok } | { ok:false, reason:'changed'|'repeat'|… }
api.reminders.snooze(ref, days, { today }) → same
api.practices.today({ date }) → { available, focus[{…, ref}], later, done, total, date, folder, streak, streakLabel }
api.practices.tick(ref, on)   → { ok, prev } | { ok:false, reason:'unreadable'|'changed'|… }
api.events.between(fromISO, toISO) → [{ name, date, time, area, path }]

weekStart and notePath are additions found while mapping Vista: it reads Rhythm's week start for its calendar and skips the reminders note in its Tasks card.

8. Testing decisions

Seams under test

  • The API (src/api.js) — the one cross-plugin seam; contract tests with a stubbed vault.
  • The module stores as they are today: reminders store, planner store, Rhythm io.js — the ported suites run unchanged against them.
  • Settings import — a pure function from (current, nudge data, fortnight data) to merged settings.
  • The plugin shell — commands, protocol handlers, ribbon/badge, page routing, with the existing obsidian stub.

What a good test looks like

Behaviour through the public interface: feed notes in, call the store/API/command, assert on the note text written and the data returned — never on private helpers.

Prior art

Nudge tests/store.test.cjs, ics.test.cjs; Fortnight store-write.test.cjs, plugin-shell.test.cjs; Rhythm io.test.cjs; Vista budget api tests.

Modules under test (critical path): io.js setFlag safety rules, planner store's Rhythm writes through io.js, reminders ICS output, settings import conflicts, API ref staleness, Vista adapter status kinds.

10. Data model sketch

Reminders note (settings.reminders.file, default Reminders.md)
  ## List heading 1─* reminder line  "- [ ] Title ⏰ HH:MM 📅 date 🔁 rule …"
Rhythm/ (settings.folder)
  Areas/*.md      rhythm: area      1─* Practices (area: [[Area]])
  Practices/*.md  rhythm: practice  *─* Log days (by name in done/skip/snooze/plan)
  Goals/*.md      rhythm: goal      body steps "- [x] date step"
  Events/*.md     rhythm: event     date, time
  Log/YYYY-MM-DD.md rhythm: log     done/skip/snooze/plan lists + appended body (reviews)
Any note: Tasks lines  "- [ ] … ⏳ day 🛫 next-week #later"   ← Fortnight cards
Planning/Fortnight.md  ## Inbox  ← Fortnight quick-add
data.json  { …Rhythm keys, name, reminders:{…Nudge}, planner:{…Fortnight}, imported:{nudge-reminders, fortnight-planner} }
